# المرحلة الخامسة: الاختبار

## الاختبار الآلي (`tests/e2e.js`)

يشغّل النظام في متصفح حقيقي على بيانات فارغة ويمر بدورة كاملة. آخر تشغيل: كل الخطوات نجحت بدون أخطاء.

| # | السيناريو | النتيجة المتوقعة | النتيجة |
|---|---|---|---|
| 1 | قرار جديد بكود غير مسجل | تُنشأ الحالة والقرار معاً، البداية حسب دورة 19–18 | ✅ |
| 2 | قرار ثانٍ لنفس الخدمة في نفس الفترة | يُرفض: تعارض مع قرار ساري | ✅ |

| 4 | إرسال حالة غير مؤكدة | زر الإرسال معطل | ✅ |
| 5 | تأكيد بدون طريقة استلام | يُرفض | ✅ |
| 6 | تأكيد كامل | MASTER يتحدث + سجل تعديلات بالقديم والجديد | ✅ |
| 7 | إرسال ضمن دفعة | دفعة برقم، عملية مسجلة باسم الموظف | ✅ |

| 10 | 3 محاولات بدون رد | «لم يتم الرد»، مسؤولية الموظف مستوفاة، الاستلام غير مكتمل | ✅ |

| 16 | تسجيل عملية يدوية | المنفذ ووقت التسجيل يُحفظان تلقائياً | ✅ |

التشغيل:

```bash
node tests/e2e.js
```

يحتاج Node.js وPlaywright (`npm i -D playwright`).

## الاختبار اليدوي المقترح قبل التشغيل الفعلي

1. **بيانات حقيقية بعد إخفائها**: صدّري حالات شهر سابق، استبدلي الأسماء والأرقام، واستورديها في الوضع المحلي.
2. **حالات قديمة وجديدة**: حالة لها 3 شهور صرف سابقة (لا تحتاج تأكيد) وحالة جديدة.
3. **تعدد القرارات والخدمات**: حالة لها كفالة + حفاضات + أثاث.
4. **عدم الرد والاسترداد والتوقف وانتهاء المدة**: كل واحدة على حالة مختلفة، ثم مراجعة التقرير الشهري.
5. **مطابقة الأرقام**: إجمالي المحوّل في التقرير = مجموع التحويلات في كشف الحسابات لنفس الشهر.
6. **تشغيل متوازٍ لشهر واحد**: العمل على الشيت الحالي والنظام معاً، ومقارنة النتائج قبل الاعتماد الكامل.
