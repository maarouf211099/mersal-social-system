# المرحلة الخامسة: الاختبار

## 1. اختبارات الوحدة — `npm test`
قواعد المرحلة والشهور (`src/lib/stage.test.ts`): 8 اختبارات — الحالة الجديدة، التعليق على الشهر السابق، التحويل ≠ الاستلام، المتابعة، الاسترداد، العيني بدون متابعة، الإيقاف، حساب الشهور وبداية الصرف (19–18).

## 2. اختبار الدورة الكاملة في متصفح — `npm run e2e`
على قاعدة **اختبار فاضية** (بيضيف بيانات تجريبية). آخر تشغيل: **40 من 40 نجح**.

| السيناريو | النتيجة المتوقعة |
|---|---|
| أول دخول | تغيير كلمة المرور المؤقتة إجباري |
| قرار بكود جديد | الحالة والقرار يتسجلوا معاً، والبداية حسب دورة 19–18 |
| قرار متعارض لنفس الخدمة | مرفوض |
| توليد الشهر | الحالة الجديدة «يحتاج تأكيد بيانات»، والإرسال غير متاح |
| تأكيد بدون طريقة استلام | مرفوض · ثم تأكيد كامل يحدّث MASTER ويحفظ القديم |
| الإرسال في دفعة · التحويل بدون مرجع · التحويل الكامل | دفعة بكود · رفض · «لا يعني الاستلام» |
| 3 محاولات بدون رد | «لم يتم الرد» + مسؤولية الموظف مستوفاة |
| استرداد كامل | «كلي» وصافي المصروف 0 |
| الشهر التالي | معلّق حتى اعتماد المشرف · الترحيل = الشهري + غير المستلم |
| بعد نهاية القرار | لا يُنشأ استحقاق |
| قبل النهاية بشهرين | يظهر في التجديد ويتبعت |
| عملية يدوية · تعديل بيانات | باسم المنفذ ووقت التسجيل · سجل تعديل بالقيمة الجديدة |
| التقارير الأربعة · CSV · سجل التدقيق | تفتح وتصدّر |
| موظف بدور «موظف» | لا يفتح الإدارة ولا يسجل تحويل |
| شاشة الموبايل | بدون تمرير أفقي |

## 3. حماية قاعدة البيانات (اتجربت يدوياً بـ psql)
حذف أو تعديل سجل تدقيق، حذف تحويل أو استرداد، ورفع مبلغ استرداد فوق التحويل — **كلها اترفضت من القاعدة نفسها**.

## 4. استيراد النظام السابق
تصدير البيانات التجريبية من صفحة HTML واستيرادها: 28 حالة · 28 قرار · 31 خدمة · 86 استحقاق · 195 عملية · 4 موظفين سابقين — واللوحة طلعت بنفس الأرقام.

## قبل التشغيل الفعلي (مقترح)
1. استيراد بيانات حقيقية على **سيرفر اختبار** ومراجعة ملفات 10 حالات يدوياً.
2. مطابقة إجمالي المحوّل في التقرير الشهري مع كشف الحسابات لنفس الشهر.
3. شهر تشغيل متوازي (الشيت الحالي + النظام) قبل الاعتماد الكامل.
