# المرحلة الأولى: تحليل النظام الحالي (v1)

الملف المحلل: `legacy/social-system-v1.html` (صفحة واحدة تعمل على قاعدة بيانات مشتركة داخل claude.ai، ومعلّمة «نسخة تجريبية · بيانات وهمية»).

## 1. ما يقوم به النظام الحالي

| الشاشة | الوظيفة |
|---|---|
| لوحة المتابعة | عدد استحقاقات الشهر، المُرسل، المتابعة المكتملة والمفتوحة، المؤجل، القرارات المستمرة، حجم الشغل بالأوزان لكل مستخدم |
| الحالات | تسجيل حالة (كود، اسم، ميلاد، جنسية، نوع، عدد أفراد، محافظة، هاتف) وملف حالة بخط زمني |
| القرارات | قرار له بنود (خدمة، قيمة شهرية، مدة، من شهر/إلى شهر)، تنبيه عند اختلاف المدة المكتوبة عن المحسوبة، منع تداخل نفس الخدمة، تجديد وإيقاف/سحب |
| الاستحقاق الشهري | توليد استحقاق لكل بند ساري في الشهر، تحديد جماعي و«تم الإرسال» / «إعادة إرسال الكارت» / «تم التسليم» |
| المتابعة | 3 أزرار: لم يرد / رد وتم الصرف / رد ولم يتم الصرف، والمتابعة تكتمل بالرد أو بعد 3 محاولات |
| إغلاق الشهر | قرارات انتهت مدتها، وقرارات عليها عدم رد لشهرين متتاليين، وتحويلها إلى «موقوف» |
| العمليات | كتالوج 72 عملية مقسمة على 5 فرق بأوزان، وتسجيل عملية (حالة أو جهة) بحالة جديد/جاري/تم |
| سجل التدقيق | آخر 200 إجراء باسم المستخدم ووقته |

### الجداول (المجموعات) الموجودة

| المجموعة | الحقول |
|---|---|
| `cases` | code, name, birth, nationality, gender, familySize, governorate, phone, createdAt, createdBy |
| `decisions` | no, code, text, donor, issueDate, status (مستمر/موقوف/مسحوب), stopReason, stopDate, stoppedBy |
| `lines` | decId, code, service, amount, months, startMonth, endMonth, mismatchNote |
| `ents` | lineId, decId, code, service, kind, month, base, amount, carried[], sent, sentAt, sentBy, resentCount, attempts[], followResult, deferred |
| `ops` | type, team, weight, scope, code, dept, date, status, notes, by, createdAt |
| `audit` | ts, by, action, target, detail |

### العلاقات

حالة (1) ← (n) قرارات ← (n) بنود ← (n) استحقاقات شهرية (واحد لكل بند لكل شهر، المفتاح `lineId_month`). العمليات مرتبطة بالحالة بالكود فقط.

## 2. نقاط القوة التي حافظنا عليها

- مفتاح الاستحقاق `lineId_month` يمنع تسجيل استحقاق مرتين لنفس الشهر.
- قاعدة بداية الصرف (القرار من 19 إلى 18 يبدأ صرفه أول الشهر التالي لشهر القطع).
- منع تداخل نفس الخدمة لنفس الحالة في قرارين ساريين.
- كتالوج العمليات وأوزانها كما هو (72 عملية).
- تسجيل اسم المستخدم ووقت كل إجراء في سجل التدقيق.

## 3. الفجوات مقارنة بالمطلوب

| المطلوب | الوضع في v1 |
|---|---|
| بيانات استلام وتحويل في MASTER (طريقة الاستلام، رقم المحفظة، المستلم، رقم المفوضية، العنوان) | غير موجودة |
| سجل تعديلات البيانات بالقيمة القديمة والجديدة | التعديل يكتب فوق البيانات بدون حفظ القيمة السابقة |
| تأكيد بيانات الحالة الجديدة بمكالمة قبل الإرسال | غير موجود |
| تسجيل التحويل (المبلغ، الطريقة، التاريخ، المرجع) منفصلاً عن الإرسال | «تم الإرسال» فقط، ولا يوجد مرجع أو تاريخ تحويل |
| التمييز بين التحويل والاستلام | موجود جزئياً (المتابعة بعد الإرسال) |
| سبب عدم الصرف والإجراء المطلوب | غير موجود |
| الاسترداد المالي | غير موجود |
| منع إدراج الشهر التالي قبل تسوية الشهر السابق | الشهر التالي يُولَّد تلقائياً ويُضاعف المبلغ (carried) بدون اعتماد |
| إسناد المهام للموظفين ومواعيد نهائية ومتأخرات | غير موجود (العمليات تُسجل بعد التنفيذ فقط) |
| التمييز بين ما أُسند للموظف وما نفذه فعلياً | غير موجود |
| تنبيه التجديد قبل نهاية القرار بشهرين | غير موجود (قائمة المنتهي بعد الانتهاء فقط) |
| خدمات متعددة (أثاث، معارض، سكن، فوط...) بدورات مختلفة | 7 خدمات ثابتة في الكود |
| تقارير شهرية وتقارير موظفين ومقارنة بالشهور السابقة وتصفية | غير موجودة |
| صلاحيات حسب الدور | أي شخص له صلاحية كتابة يفعل كل شيء |
| نسخ احتياطي وتصدير | غير موجود |

## 4. المشكلات والمخاطر التي وجدناها

1. **رقم القرار** يُحسب بعدد القرارات + 1، فلو سجّل موظفان قراراً في نفس اللحظة يأخذان نفس الرقم. → في v2: أكبر رقم موجود + 1، ومنع الرقم المكرر.
2. **الترحيل التلقائي للمبلغ** (`carried`) يضاعف استحقاق الشهر التالي بدون أي اعتماد، وقد يصبح مزدوجاً لو رد المستفيد متأخراً. → في v2: الاستحقاق التالي يُعلَّق حتى اعتماد المشرف، والترحيل يتم مرة واحدة ويُعلَّم الشهر السابق «مُسوّى».
3. **تعديل بيانات الحالة** يمسح القيمة القديمة. → في v2: جدول `changes`.
4. **سجل التدقيق** يعرض آخر 200 فقط. → في v2: آخر 1000 مع بحث.
5. **حالة العملية** يمكن تغييرها من أي مستخدم بدون تسجيل القيمة السابقة. → في v2: تُسجل القيمة القديمة والجديدة، والمشرف فقط يغيّر عمليات غيره.
6. **قرارات انتهت** تبقى «مستمر» حتى يغلقها أحد يدوياً، وتظهر في المؤشرات كنشطة. → في v2: تُعرض تلقائياً «منتهي» ولا يُنشأ لها استحقاق.
7. **ربط العمليات بالحالة بالكود فقط** بدون ربط بالاستحقاق. → في v2: العمليات التلقائية تحمل مرجع الاستحقاق أو الدفعة.

## 5. أثر التطوير على البيانات الحالية

- **لا يُحذف أي حقل ولا تتغير أسماء المجموعات الست.** كل الحقول الجديدة إضافية واختيارية.
- الاستحقاقات القديمة (بدون علامة `v2`) تُقرأ كما هي: «تم الإرسال» في المالي يُعامل كتحويل بقيمة الاستحقاق حتى لا تنقطع التقارير، و`deferred`/`carried` تُفسَّر بنفس منطق v1.
- القرارات القديمة بحالة «موقوف» بسبب «انتهاء المدة» تبقى كما هي، والجديدة تُغلق بحالة «منتهي».
- يمكن تشغيل v2 على نفس قاعدة بيانات v1 مباشرة (نفس الصفحة) بدون ترحيل بيانات.
