# نظام الإدارة الاجتماعية — مؤسسة مرسال

نظام تشغيل كامل للإدارة الاجتماعية: من إضافة القرار، لتأكيد بيانات الحالة، والإرسال ضمن دفعة الصرف، والتحويل، ومتابعة استلام المستفيد، والاسترداد، حتى انتهاء مدة القرار والتجديد. **كل عملية بتتسجل باسم القائم بها وتاريخ ووقت تسجيلها.**

| | |
|---|---|
| التقنية | Next.js 15 + Prisma + PostgreSQL (schema اسمها `social`) — نفس تقنية بوابة مرسال والتذاكر |
| البورت | 3011 |
| الدخول | بالإيميل وكلمة المرور، أو من **بوابة مرسال** مباشرة (مفتاح النظام في البوابة: `social`) |
| التشغيل | pm2 على السيرفر، نشر بأمر واحد مع رجوع تلقائي للنسخة السابقة لو فشل |

## الشاشات
| الشاشة | ماذا تفعل |
|---|---|
| لوحة المتابعة | تنبيهات (تأكيد بيانات، معلّق، متأخر، تجديد، منتهي، استرداد) + مؤشرات التشغيل والمالية والخدمات والموظفين + اتجاه 6 شهور |
| مهامي | المطلوب من الموظف الآن ومؤشراته الشخصية |
| الحالات | MASTER موحد لكل كود: بحث وتصفية، ملف الحالة الكامل (القرارات، الاستحقاقات، التحويلات، الاستردادات، العمليات، المرفقات، سجل تعديل البيانات بالقديم والجديد) · تنبيه لو الهاتف أو المفوضية أو الرقم القومي أو المحفظة مسجلين لحالة تانية |
| القرارات | إضافة سريعة (كود + اسم + خدمة + مدة + بداية + نهاية) — الكود الجديد يتسجل تلقائياً · منع التعارض · تجديد · إيقاف/سحب · تصحيح خطأ الإدخال (مشرف، بسبب، والقديم محفوظ) |
| دورة الصرف | توليد استحقاقات الشهر للمالي والكروت والعيني والخدمات (سكن، علاج، متابعة)، مرحلة كل حالة، الإرسال الجماعي في دفعة، التحويل الجماعي، إعادة إرسال الكارت، صفحة لكل استحقاق فيها الخطوة المطلوبة ومرفقاته |
| المتابعة | لم يرد / رد وتم الصرف / رد ولم يتم الصرف (سبب + إجراء + مهمة معالجة) · 3 محاولات |
| الاستردادات | كلي/جزئي تلقائي، مربوط بالتحويل ومرجعه، صافي المصروف، التسوية |
| التجديد والانتهاء | القرارات اللي تنتهي خلال شهرين، الإرسال للتجديد، تسجيل قرار التجديد، إغلاق المنتهي، عدم الرد لشهرين متتاليين (إيقاف جماعي)، تصدير القائمة |
| توزيع المهام | مهام تلقائية من دورة العمل + يدوية، إسناد جماعي، الحِمل، المتأخر، الإرجاع للتصحيح |
| العمليات | سجل موحد لكل إجراء (تلقائي ويدوي) بالمنفذ ووقت التسجيل ومرفقاته، 72 نوع عملية بأوزانها |
| التقارير | شهري (مع مقارنة بالشهر السابق)، الموظفين، كل العمليات، مقارنة 6 شهور · تصفية بالموظف والخدمة وحالة القرار والمحافظة والجنسية · CSV · طباعة |
| سجل التدقيق | كل إجراء — محمي على مستوى قاعدة البيانات (لا تعديل ولا حذف) |
| الإدارة | المستخدمون والأدوار، الإعدادات، الخدمات وأنواع العمليات، استيراد بيانات النظام السابق |

## الحماية
- **الصلاحيات على السيرفر**: كل إجراء بيتفحص على السيرفر حسب الدور (مدير، مشرف، مالي، موظف، قراءة) — مش بس إخفاء زرار.
- **قاعدة البيانات نفسها بتمنع**: تعديل أو حذف سجل التدقيق وسجل تعديل البيانات، وحذف التحويلات والاستردادات ومحاولات الاتصال، والمبالغ السالبة، واسترداد أكبر من التحويل، وتكرار استحقاق نفس الشهر، وتكرار كود الحالة أو رقم القرار.
- الجلسة بتتقري من القاعدة في كل طلب: إيقاف موظف أو تغيير دوره بيسري فوراً.
- المرفقات على السيرفر (خارج فولدر النسخة)، لا تُحذف، ولا تفتح إلا بعد الدخول.
- نسخة احتياطية يومية: `scripts/backup.mjs` (القاعدة + المرفقات، بيحتفظ بآخر 30).

## التشغيل على السيرفر — أمر واحد
```
git clone https://github.com/maarouf211099/mersal-social-system
cd mersal-social-system
node scripts/setup-server.mjs --dir D:\apis\mersal-social --admin-email mahmoud.maarouf@mersal-ngo.org
```
التفاصيل والربط ببوابة مرسال: [`docs/07-deploy.md`](docs/07-deploy.md)

**تحديث النظام بعد كده:**
```
cd mersal-social-system && git pull && set DEPLOY_DIR=D:\apis\mersal-social && node scripts/deploy.mjs
```

## التطوير
```
cp .env.example .env        # وعدّل DATABASE_URL
npm ci
npx prisma migrate deploy && node scripts/seed.mjs
npm run dev                 # http://localhost:3011
```
قبل أي commit:
```
npm run typecheck && npm test && npm run build
```
اختبار الدورة الكاملة في متصفح (على قاعدة اختبار فاضية فقط): `BASE_URL=http://localhost:3011 npm run e2e`
